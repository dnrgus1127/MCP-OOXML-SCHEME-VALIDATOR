# 에디터 사용성 감사 및 개선 설계

- 날짜: 2026-06-07
- 범위: `packages/desktop` XmlEditorScreen 화면 전체 (Monaco 편집 영역 + 툴바 + 문서 트리 + 우측 패널군)
- 기준 사용자: 혼합 (OOXML 파워유저 + 입문/QA 사용자), 양쪽 균형
- 기반 가이드: `agent/desktop-ui-ux-agent-guide.md` (WCAG 2.2 AA, NN/g 10 휴리스틱, 상태 모델, 성능 UX)

## 1. 목적

에디터 화면 전체를 가이드가 스스로 내건 품질 기준에 비춰 감사하고, 발견된 사용성
이슈를 심각도×빈도 트리아지로 묶어 실행 가능한 작업 목록(P0/P1/P2)으로 만든다.
"보기 좋은 UI"가 아니라 "업무 성공률이 높은 UI"를 우선한다.

## 2. 감사 결과 — 발견 항목과 근거

각 항목은 실제 코드 근거(파일:라인)를 동반한다.

### A. 접근성 (가이드 의무 영역 — 실제 위반)

- **A1. 문서 트리 키보드 사용 불가** — `components/DocumentTree.tsx`의 트리 항목이
  `<div onClick>`뿐. `role=treeitem`, `tabIndex`, 화살표 키 탐색, `aria-expanded`,
  `aria-selected` 부재. 파트 탐색이 핵심 작업인데 마우스 전용.
- **A2. 검증 결과 항목 키보드 사용 불가** — `components/ValidationPanel.tsx`의 행이
  `<div onClick>`(펼치기/이동). 키보드 포커스·조작 불가, `aria-expanded` 없음.
- **A3. 에디터 화면 전역 포커스 표시 부재** — `styles/globals.css`에 홈/설정 화면용
  `:focus-visible`는 있으나 툴바 버튼·트리·패널 행에는 포커스 스타일이 없음.
  키보드 사용자가 현재 위치를 알 수 없음.

### B. 시스템 상태 가시성 / 피드백

- **B1. 검증 진행 표시 없음** — `screens/XmlEditorScreen.tsx`의 `validate()`는
  await하지만 진행 중 로딩/스피너 UI가 없음. 대용량 문서에서 무반응처럼 보임.
- **B2. 오류 배너에 복구 행동 없음** — 상단 `error-banner`가 메시지 + × 만 제공.
  가이드 3.4 "원인 + 영향 + 해결 행동" 미충족.
- **B3. 검증 오류 코드 원문 노출** — `XML_PARSE_ERROR` 같은 코드가 그대로 노출되고
  "다음 행동" 안내가 없음. 입문/QA 사용자 기준 장벽.

### C. 데이터 무결성 위험

- **C1. `formatXml` 공백 파괴 위험** — `components/XmlEditor.tsx:45`의 정규식
  포매터가 `>\s+<`를 제거. `xml:space="preserve"`, `<w:t>`/`<a:t>` 텍스트 런 등
  유의미한 공백 콘텐츠를 손상시킬 수 있음. 파일을 열 때마다 `formatXml(content)`로
  자동 재포맷되어, 열기만 해도 dirty 표시 및 저장 시 변형된 공백이 기록될 가능성.
  (실제 dirty 전이 여부는 구현 전 검증 필요)

### D. 정보 구조 / 공간 경쟁

- **D1. 우측 패널 4중 적층** — `right-panels`에 검색·검증·인스펙터·스키마참조가
  세로로 쌓임(기본으로 검증+인스펙터+스키마참조 동시 노출). 리사이즈·탭 전환 없이
  좁게 경쟁. 정보 밀도 과다.

### E. 일관성 / 콘텐츠

- **E1. UI 언어 혼용** — 툴바·검증 패널은 영어("Save", "Document has errors"),
  에디터 버튼은 한국어("전체 접기/펼치기"). 가이드 4장 일관성·다국어 준비 위반.
- **E2. 닫기 버튼이 텍스트 "x"/"×"** — 컴포넌트마다 제각각, 타깃 크기 기준 미흡.

### F. 효율성 / 파워유저

- **F1. 단축키 빈약** — 재검증만 설정 가능. Format·접기/펼치기·패널 토글·파트
  이동에 단축키와 시각적 힌트가 없음.

### G. 성능 UX

- **G1. 편집마다 전체 문서 재분석** — `screens/XmlEditorScreen.tsx`의 스키마참조
  분석이 `modifiedContent` 변경마다(300ms 디바운스) 전체 파일 재인코딩 + 분석.
  대용량 파일에서 INP 악화.

## 3. 우선순위 작업 목록 (심각도×빈도 트리아지)

A군(접근성)과 C1(데이터 무결성)은 가이드 의무 및 무결성 사유로 협상 불가 P0 고정.
나머지는 사용 빈도 × 부딪혔을 때의 치명도로 배치.

### P0 — 반드시 (가이드 의무 위반 + 데이터 무결성)

| ID | 작업 | 완료 기준 |
|----|------|-----------|
| P0-1 | 문서 트리 키보드 접근성 (A1) | `role=tree/treeitem`, 화살표·Enter·←/→ 탐색, `aria-expanded`/`aria-selected`, 로빙 tabindex |
| P0-2 | 검증 패널 행 키보드 접근성 (A2) | 행을 버튼/`role` 부여, Enter로 펼침·이동, `aria-expanded` 반영 |
| P0-3 | 에디터 화면 전역 포커스 표시 (A3) | 툴바·트리·패널 행 모두 `:focus-visible` 윤곽선, 대비 3:1 이상 |
| P0-4 | `formatXml` 공백 파괴 방지 (C1) | 먼저 dirty 전이 여부 검증 → 열기 시 자동 재포맷 제거(또는 비파괴 포맷), `xml:space=preserve`/텍스트 런 보존 |

### P1 — 고빈도 × 중상 심각도

| ID | 작업 | 완료 기준 |
|----|------|-----------|
| P1-1 | 검증 진행 상태 UI (B1) | 검증 중 스피너/비활성화 + 완료 피드백, 대용량에서 무반응 구간 제거 |
| P1-2 | 검증 오류 메시지 인간 친화화 (B3) | 코드→사용자 문구 매핑, 각 오류에 "다음 행동" 1줄 |
| P1-3 | 우측 패널 구조 개편 (D1) | 4중 적층 → 탭 전환 또는 리사이즈 핸들, 한 번에 보이는 정보량 통제 |
| P1-4 | UI 언어 정책 통일 (E1) | 한/영 혼용 해소(정책 1개 선택), 문구 일관화 |

### P2 — 개선 여지 (저빈도 또는 저심각)

| ID | 작업 | 완료 기준 |
|----|------|-----------|
| P2-1 | 오류 배너 복구 행동 (B2) | 원인+영향+다음 행동, 재시도/닫기 경로 |
| P2-2 | 단축키 확장 + 힌트 (F1) | Format·접기/펼치기·패널 토글 단축키, 버튼 title에 단축키 표기 |
| P2-3 | 스키마참조 분석 증분화 (G1) | 편집마다 전체 재인코딩 제거, 스코프 축소/캐시 |
| P2-4 | 닫기 버튼·타깃 일관화 (E2) | 공용 닫기 컴포넌트, 최소 24×24 타깃 |

## 4. 구현 순서와 검증

1. **P0-4를 가장 먼저 검증부터** 한다. 파일을 열기만 해도 dirty가 되는지, 저장 시
   공백이 변형되는지 재현한다. 재현되면 "열기 시 자동 재포맷 제거"를 최소 수정으로
   적용하고, Format은 명시적 사용자 액션일 때만 동작하도록 한다.
2. P0-1 ~ P0-3 접근성은 WAI-ARIA APG 패턴(Tree View, Disclosure)을 따른다.
   네이티브 시맨틱 우선, ARIA는 보조로만.
3. P1, P2는 P0 머지 후 별도 단계로 진행한다.

## 5. 비범위 (YAGNI)

- 새 검증 엔진/스키마 기능 추가 없음 (이번 작업은 사용성 한정).
- 비교 모드의 신규 기능 확장 없음 (기존 동작 유지).
- 테마/디자인 토큰 전면 개편 없음 (포커스 표시 등 필요한 토큰만 확장).

## 6. 결정 필요 항목 (구현 중 확정)

- **언어 정책(P1-4)**: 한국어 우선 vs 영어 우선 — 기존 한국어 비중(가이드·버튼 일부)을
  고려하면 한국어 우선이 자연스러우나, 확정 전까지 P1-4는 보류.
- **우측 패널 개편(P1-3)**: 탭 전환 vs 리사이즈 — 정보 밀도와 동시 참조 필요성을
  근거로 구현 단계에서 결정.
